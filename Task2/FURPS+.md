| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**  | **Функциональные (Functionality)**     |              |
|     | **_Интернет-банк_**                |              |
| F1  | Интернет-банком могут пользоваться только авторизованные пользователи |              |
| F2  | Пользователь регистрируется по номеру телефона, паролю и вводит одноразовый код из СМС | На данный момент уже логично, что есть система регистрации, но ввиду текущей офлайн направленности банка следует перевести предварительную регистрацию в сам интернет-банк. После подтверждения документов в офисе становятся доступны основные функции приложения |
| F3  | Зарегистрированный пользователь проходит авторизацию по номеру телефона, паролю и СМС-коду | |
| F4  | Пользователь на главной странице может перейти к продуктам банка - список доступных депозитов с актуальными ставками и персональными предложениями по ним | | 
| F5  | Пользователь может на странице продуктов банка подать заявку на открытие нового депозита, указав счет и сумму депозита, а затем подтвердив с помошью СМС-кода | |
| F6  | Система должна отправлять СМС-уведомление о статусе обработки заявки | |
| F7  | Пользователь может на главной странице перейти в свой профиль | |
| F8  | На странице своего профиля пользователь может просмотреть данные своего профиля (номер телефона, ФИО) и изменить пароль | |
|     | **_Сайт_**                         |              |
| F9 | Пользователь на главной странице может перейти к продуктам банка - список доступных депозитов с актуальными ставками | |
| F10 | Пользователь может оставить заявку на открытие депозита, оставив свой номер телефона и ФИО | Для подтверждения заявки с клиентом свяжется сотрудник кол-центра |
| F11 | Пользователь может авторизоваться на сайте, используя учетную запись интернет-банка. После авторизации его перенаправляет в интернет-банк | |
|     | **_Общее_** | |
| F12 | Система должна хранить актуальные ставки по депозитам в БД | |
| F13 | Система должна предоставлять доступ к ставкам сотрудникам бэк-офисам кредитов и депозитов | |
| **U**   | **Удобство использования (Usability)** |              |
| U1  | Дизайн сайта и интернет-банка должны придерживаться системы дизайна приложений банка (цвета, брендированные элементы...) | |
| U2  | Интерфейс сайта должен иметь дополнительную версию для слабовидящих | Т.к. основная клиентская база банка - люди старшего возраста, это поможет им перейти на онлайн взаимодействие с банком |
| U3  | Сайт и интернет-банк должны содержать раздел со справочной информацией по работе с системой | |
| **R**   | **Надёжность (Reliability)**           |              |
| R1  | На этапе MVP время простоя интернет-банка может быть не более одного дня | В дальнейшем требование будет ужесточено |
| R2  | Время работы 24/7 | |
| R3  | Доступность 99,9% | |
| R4  | При возникновении ошибок система должна переключатсья на резервный ЦОД | В дальнейшем следует использовать оба с распределением нагрузки |
| R5  | При использовании функционала кэширования, срок хранения кэша должен быть 30 мин | Следует уточнить с командой АБС и менеджерами бэк-офиса |
| **P**   | **Производительность (Performance)**   |              |
| P1  | Время отклика ≤ 200 мс             | Команда АБС просит избежать прямой работы с API АБС. На этапе MVP можно кэшировать данные по ставкам в системе, но сообщать пользователю об уточнении ставки на этапе оформления заявки |
| P2  | На этапе MVP система должна поддерживать 250 одновременных пользователей | |                       |              |
| **S**   | **Поддерживаемость (Supportability)**  |              |
| S1  | Должна быть поддержка интеграционного тестирования | |
| S2  | Должны быть настроены системы мониторинга и логирования | |
| S3  | Должно быть настроено автоматическое тестирование при развертывании | |
| S4  | Должно быть настроено автоматические уведомления о сбоях и проблемах в системе | |
| S5  | Развертывание нового функционала должно быть реализовано канареечным способом | |
| **+R**  | **+ Ограничения (Restrictions)**       |              |
| R1  | Данные с сайта и интернет-банка должны передаваться в зашифрованном виде | |
| R2  | Пароли пользователей должны храниться в виде хэша | |
| R3  | Желательно использование технологий из числа имеющихся компетенций команды разработки | |
| R4  | Новые технологии должны быть совместимы с имеющимся стеком | |
| R5  | При необходимости внедрения очередей желательно использовать Kafka | |
| R6  | При внедрении Kafka доработка системы должна осуществляться по паттерну strangler fig | |
| R7  | Изменения в системе должны документироваться в виде журнала ADL | |
| R8  | Следует по возможности избегать прямого обращения к API АБС | Можно решить проблему через использование кэширования в Redis |
